Что такое Django App?

В Django проект состоит из приложений (App). Каждое приложение отвечает за свою часть сайта.

Аналогия: Дом и комнаты

Проект — это целый дом. А каждое приложение — это отдельная комната в этом доме. Кухня отвечает за еду, спальня — за сон, гостиная — за отдых. Так же и в Django: приложение blog отвечает за статьи, shop — за товары, users — за пользователей.

Проект = Дом
Весь сайт целиком. Содержит настройки и все приложения.
App = Комната
Отдельная часть сайта: блог, магазин, профиль пользователя.
Переиспользование
Приложение можно перенести в другой проект — как мебель из одной комнаты в другую.

Подключение приложения

Django не узнает о новом приложении, пока мы не добавим его в настройки. Открой файл config/settings.py и найди список INSTALLED_APPS:

config/settings.py
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',

    # Наши приложения
    'blog',
]

Важно!

Добавь 'blog', в самый конец списка. Не забудь кавычки и запятую! Без этого шага Django не увидит приложение и все следующие шаги не сработают.

Что такое модель?

Модель — это описание данных. Она говорит Django, какую информацию нужно хранить в базе данных.

Аналогия: Таблица в Excel

Представь таблицу в Excel. Каждая строка — это одна запись (например, одна статья). Каждый столбец — это поле (заголовок, текст, дата). Модель в Django — это описание такой таблицы на языке Python.

Заголовок (title)
Короткий текст — название статьи. Ограничен 255 символами.
Содержание (content)
Длинный текст — основная часть статьи. Без ограничения длины.

Создание модели Post

Откройте файл blog/models.py и замените его содержимое на этот код:

blog/models.py
from django.db import models


class Post(models.Model):
    title = models.CharField(max_length=255)
    content = models.TextField()

    def __str__(self):
        return self.title
from django.db import modelsИмпортируем модуль models из Django — в нём находятся все инструменты для создания моделей.
class Post(models.Model):Создаём класс Post, который наследуется от models.Model. Это значит — «Post — это модель Django».
title = models.CharField(max_length=255)CharField — поле для короткого текста. max_length=255 — максимум 255 символов. Подходит для заголовков.
content = models.TextField()TextField — поле для длинного текста без ограничения. Подходит для содержания статьи.
def __str__(self):Специальный метод, который говорит Python, как отображать объект в виде текста.
return self.titleКогда Django показывает объект Post — он покажет его заголовок, а не непонятный текст вроде «Post object (1)».

Что такое миграции?

Мы описали модель в Python-коде, но база данных пока ничего об этом не знает. Миграции — это мост между кодом и базой данных.

1
makemigrations
Django читает модель и создаёт файл-инструкцию — что нужно изменить в базе данных. Как чертёж дома перед строительством.
2
migrate
Django выполняет инструкцию и создаёт таблицу в базе данных. Как строитель строит дом по чертежу.

Простыми словами

makemigrations = «Запомни, что я хочу изменить»
migrate = «Сделай это изменение прямо сейчас»

Эти две команды нужно выполнять каждый раз, когда ты меняешь модели!

Выполнение миграций

Откройте терминал и выполните две команды по очереди:

Терминал — Шаг 1: Создание миграции
python manage.py makemigrations

В терминале ты увидишь сообщение:

Результат
Migrations for 'blog':
  blog/migrations/0001_initial.py
    - Create model Post
Терминал — Шаг 2: Применение миграции
python manage.py migrate

Django применит все миграции и создаст таблицы в базе данных. Ты увидишь список с надписями OK.

Готово!

Теперь в базе данных есть таблица blog_post с полями id, title и content. Django автоматически добавил поле id — уникальный номер каждой записи.

Что такое Admin Panel?

Django Admin Panel — это готовая панель управления сайтом. Она позволяет добавлять, редактировать и удалять данные через удобный интерфейс в браузере — без написания кода!

Добавлять данные
Создавай новые статьи, товары, пользователей прямо в браузере.
Редактировать
Изменяй заголовки, тексты и другие поля одним кликом.
Удалять
Удаляй ненужные записи — Django спросит подтверждение.
Безопасность
Только администратор с паролем может войти в панель.

Регистрация модели в Admin Panel

Чтобы модель Post появилась в админ-панели, нужно зарегистрировать её. Откройте файл blog/admin.py и замените его содержимое:

blog/admin.py
from django.contrib import admin
from .models import Post

admin.site.register(Post)
from django.contrib import adminИмпортируем модуль admin из Django — он уже был в файле по умолчанию.
from .models import PostИмпортируем нашу модель Post из файла models.py. Точка . означает «из текущей папки».
admin.site.register(Post)Регистрируем модель Post в админ-панели. Теперь Django покажет её в панели управления.

Запомни!

Каждую модель нужно регистрировать отдельно. Если создашь модель Category — добавь admin.site.register(Category).

Создание суперпользователя

Чтобы войти в админ-панель, нужен аккаунт администратора — суперпользователь (superuser). Выполни команду в терминале:

Терминал
python manage.py createsuperuser

Django попросит ввести данные. Вводи по очереди:

Терминал — процесс создания
Username (leave blank to use 'user'): admin
Email address: admin@example.com
Password: ********
Password (again): ********
Superuser created successfully.
UsernameИмя пользователя для входа. Мы написали admin, но можно выбрать любое имя.
Email addressЭлектронная почта. Можно ввести любую — на уроке это не важно.
PasswordПароль для входа. Символы не отображаются при вводе — это нормально! Просто вводи и нажимай Enter.
Password (again)Повтори тот же пароль для подтверждения.

Не волнуйся!

Когда ты вводишь пароль — на экране ничего не появляется. Это сделано для безопасности. Просто введи пароль и нажми Enter. Если Django скажет, что пароль слишком простой — введи y и нажми Enter, чтобы подтвердить.

Практика на уроке

Выполни все три задания прямо сейчас!

Задание 1: Создай модель Category

Открой blog/models.py и добавь новую модель Category после модели Post:

blog/models.py
from django.db import models


class Post(models.Model):
    title = models.CharField(max_length=255)
    content = models.TextField()

    def __str__(self):
        return self.title


class Category(models.Model):
    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name

Задание 2: Зарегистрируй Category в admin.py

blog/admin.py
from django.contrib import admin
from .models import Post, Category

admin.site.register(Post)
admin.site.register(Category)

Задание 3: Выполни миграции

Терминал
python manage.py makemigrations
python manage.py migrate

Запусти сервер и проверь — в админ-панели должна появиться модель Categorys рядом с Posts!
